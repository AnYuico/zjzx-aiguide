## 4. 秒杀提交

四档使用互不重叠的 50、100、200、2 名用户。活动 ID 就绪后运行
`New-ZjzxJmeterCohorts.ps1` 生成专用 CSV，并严格按
`Before -> JMeter -> AfterConsumer -> 用户取消 -> AfterTimeout` 执行。

容量测试需在隔离环境把 Gateway 的 `SECKILL_IP_RATE_LIMIT` 和
`SECKILL_ACTIVITY_RATE_LIMIT` 临时提高到 1000，否则单机测试会先命中默认
20 次/秒 IP 限流。测试后恢复默认值。

## 5. Agent 对话

PGVector/Ollama 混合检索已测 20/30 并发，容量拐点位于 20 至 30；DeepSeek
对话已测 1/2/5 小并发，5 并发中 3 次真实模型响应、2 次确定性回退，未出现
HTTP 429/5xx。Agent 重启后需复测一次回退原因指标。

## 6. 本轮排除项

- 不调用 `/api/order/alipay/**`。
- 不验证支付宝 SDK、签名、回调或支付成功事件。
- 不批量制造支付记录。
- 不修改现有 SKU 价格、商品状态或历史订单。
- 不直接向 Redis 写入秒杀库存，必须通过活动发布接口预热。

压测结束后使用 `scripts/jmeter/sql/verify-order-submit.sql` 进行只读对账。
